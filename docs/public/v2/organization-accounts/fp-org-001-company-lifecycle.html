9. API 详细设计

方法路径要点
GET/POST/api/v1/admin/companies分页筛选；创建使用独立 Idempotency-Key 请求头，与生成 requestId 无关
GET/PATCH/api/v1/admin/companies/{companyId}详情与名称、状态修改
PATCH/api/v1/admin/users/{userId}/status仅平台管理员可停用、归档或恢复公司管理员；操作前保证该公司至少保留一个 active company_admin
PATCH/api/v1/admin/users/{userId}/company-role仅平台管理员任免公司管理员；降级前执行最后管理员保护

13. 日志 / 监查 / 运用设计

审计公司创建、名称变更、启停和首个管理员设置；监控停用公司仍产生新任务、无管理员公司和公司关系缺失。

14. 外部接口 / 文件 / 批处理 / 通知

无新增外部接口。推定 公司停用时向公司管理员发送站内通知；通知失败不回滚停用。

15. 数据迁移 / 初期数据 / 兼容性

项目未上线，直接由 seed 创建平台管理员、示例公司和公司管理员；不创建个人组织，不回填旧普通账号。平台管理员不绑定公司。

16. 测试设计观点

  • 公司创建事务任一步失败不得留下半成品。
  • 停用后成员新旧会话均不可调用业务 API。
  • 平台管理员账号不受公司停用影响。
  • 公司列表汇总不得跨公司错算。
