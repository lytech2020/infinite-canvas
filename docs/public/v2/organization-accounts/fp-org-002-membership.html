FP-ORG-002 成员、角色与账号归档

一个普通用户只能属于一个公司；归档账号但保留全部历史数据

1. 文档信息

状态：确认済。角色为平台管理员、公司管理员、公司成员；不保留个人用户。

2. 功能点输入整理

目的公司管理员添加、维护和归档本公司员工
确认行为归档后禁止登录和新写入，历史数据继续真实保留并归属原公司
Changed Behavior删除 POST /auth/register、登录页注册模式和 registration_open；数据库 CHECK 强制普通用户 companyId 非空、平台管理员为空
范围外跨公司加入、成员转移、物理删除、共享账号

4. 最小修改方针

继续复用邮箱密码和服务端会话；在用户记录上保存唯一 companyId、companyRole、三态 status、archivedAt 和 mustChangePassword。认证只以 status 判定，archivedAt 仅记录归档时间。归档撤销全部会话，不搬迁或删除业务数据。

9. API 详细设计

方法路径说明
GET/POST/api/v1/company/members强制当前公司范围，只创建 member；初始密码只在创建响应显示一次，数据库只存哈希且无二次查看接口
GET/PATCH/api/v1/company/members/{userId}普通成员详情；禁止 self 与 company_admin 目标
POST/api/v1/company/members/{userId}/archive归档普通成员并撤销全部会话；不执行“最后管理员”校验
POST/api/v1/admin/users/{userId}/password-reset仅平台管理员重置，强审计并置 must_change_password；生成的 8～16 位一次性密码只在响应显示一次
POST（复用既存）/api/v1/auth/password强制改密页提交 currentPassword/newPassword；成功后置 must_change_password=false 并撤销其他会话。must-change 中间件白名单固定为 GET /auth/me、POST /auth/password、POST /auth/logout
删除/api/v1/auth/registerV2 不保留自助注册

ID规则
PERM-FP-ORG-002-001平台管理员可管理全部公司用户；公司管理员的成员接口固定当前 companyId，且目标必须为本公司普通 member
PERM-FP-ORG-002-002公司管理员禁止操作自己、同级 company_admin 或其他公司用户；公司管理员任免及最后管理员保护仅由平台管理员接口执行

合法角色矩阵：平台管理员为 role=admin 且 companyId/companyRole 为空；公司管理员与成员均为 role=user、companyId 非空，companyRole 分别为 company_admin/member。公司管理员只能管理普通成员，不能操作自己或同级管理员；公司管理员任免由平台管理员完成。

14. 外部接口 / 文件 / 批处理 / 通知

首期不依赖 SMTP；删除注册接口、登录页注册模式和 registration_open 设置。公司管理员创建成员时得到一次性初始密码，成员首次登录强制改密；后续密码重置仅平台管理员执行。邮件邀请可后续扩展。

16. 测试设计观点

  • TEST-FP-ORG-002-001：同一用户不能加入第二家公司。
  • TEST-FP-ORG-002-002：归档立即撤销会话，queued 取消，running 完成结算。
  • TEST-FP-ORG-002-003：归档后项目和用量仍按原成员展示。
  • TEST-FP-ORG-002-004：注册接口不存在且普通用户 companyId 必填。
  • TEST-FP-ORG-002-005：8～16 位初始/重置密码能够登录；must_change_password 会话仅可调用 me、password、logout，改密成功后恢复正常权限。
  • TEST-FP-ORG-002-006：公司管理员不能操作自己、同级管理员或其他公司成员。
