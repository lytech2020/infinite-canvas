FP-ORG-005 公司专属供应商渠道与密钥

供应商渠道、Key 和路由仅由平台管理员配置，公司端永不获得上游配置

1. 文档信息

状态：确认済。本文“供应商渠道（Provider）”和“Base URL”均指后端调用 AI 供应商的上游地址与凭据，与公司访问本系统的网址无关。公司管理员不能配置上游配置；使用专属 Key 仍正常计积分。

2. 功能点输入整理

目的平台可为指定公司绑定独立供应商账号，同时统一掌控密钥安全和模型治理
新行为渠道作用域、公司模型路由绑定、公共回退、密钥轮换
范围外公司自带 Key、自助测试 Key、公司管理员查看密钥

4. 最小修改方针

继续使用现有 provider 密钥加密能力；为 provider 增加 platform/company 作用域或公司关系，通过绑定表选择路由。模型与 Key 不复制到公司前端。

12. 校验 / 错误处理设计

条件错误码
绑定的 Provider 属于其他公司INVALID_PROVIDER_SCOPE
binding.provider.api_format != model.provider.api_formatPROVIDER_API_FORMAT_MISMATCH；保存绑定和执行路由时双重校验，禁止跨协议静默映射
专属 Provider 停用且禁止回退MODEL_ROUTE_UNAVAILABLE
Key 解密失败PROVIDER_SECRET_INVALID，并触发平台告警
公司角色访问整类平台 Provider APIFORBIDDEN 403；角色级不可达，不是具体跨租户资源查询

MODEL_ROUTE_UNAVAILABLE 的 details 不得包含 Provider 名称、Base URL、Deployment 或 API Version 片段。

13. 日志 / 监查 / 运用设计

密钥新建、轮换、清空、渠道启停和绑定变更必须审计；日志只记录 providerId、companyId 和掩码，不记录明文。监控专属渠道失败率和公共回退次数。

14. 外部接口 / 文件 / 批处理 / 通知

供应商协议继续复用现有适配器。密钥轮换允许短期双 Key 的需求尚未确认；首期采用一次性替换，保存前执行可选连接测试。

15. 数据迁移 / 初期数据 / 兼容性

项目未上线，由 seed 直接创建 platform 作用域 Provider。公司专属 Provider 必须由平台管理员新建，不复制公共密钥。

16. 测试设计观点

  • TEST-FP-ORG-005-001：专属 Provider 优先和公共回退开关。
  • TEST-FP-ORG-005-002：不能跨公司绑定 Provider；公司端不可见上游配置。
  • TEST-FP-ORG-005-003：Azure Deployment 和 API Version override 生效且不影响公共 Provider。
  • TEST-FP-ORG-005-004：apiFormat 不一致时保存和运行均拒绝。
  • TEST-FP-ORG-005-005：保存前连接测试使用 override 后的完整路由。
  • TEST-FP-ORG-005-006：密钥轮换后新任务使用新凭据，历史用量保留原 providerId 和路由快照。
