14. 外部接口 / 文件 / 批处理 / 通知

  • 每日账户一致性核对和预占回收沿用 V1 临时上传清理方式，在单副本 API 进程定时器内运行，不引入 Redis 或队列；多副本部署前必须改为带分布式锁的独立 worker。
  • 应用启动期既有 stale queued/running job 清理必须调用积分服务，在同一事务将任务置终态并 release 对应 active reservation；不得只改 job 状态。定时 TTL 回收仍作为兜底。
  • 余额和周期用量 80%/100% 站内预警；通知渠道后续可扩展邮件。
  • CSV 首期同步导出，限制时间窗口和行数，固化当前公司范围并写导出审计；不提供敏感内容批量导出。
  • canvas-agent 是用户本地进程，只与浏览器通过本地 connect token 通信，不直接访问云端后端。Agent 线程由 Web 端写入既有 /api/v1/user-data 的 agent_chat 命名空间，附件写入 /api/v1/uploads；公司边界复用 FP-ORG-003 的 user_data 复合主键和 uploads 复合归属。云端接口忽略请求体中的任何 companyId，只从 Web 会话解析。
