4. 最小修改方针

  1. 在现有用户、模型、供应商渠道、生成任务和用量记录外增加公司关系与积分域，不改供应商底层协议。
  2. 删除自助注册和 registration_open，普通用户在数据库层强制绑定公司。
  3. 统一在认证上下文解析 companyId，所有账号业务查询通过服务端数据范围过滤。
  4. 使用授权关系表表达公司和成员模型权益，不复制模型定义。
  5. 使用公司供应商渠道绑定覆盖公共渠道，并允许覆盖 Azure Deployment/API Version，不向公司前端暴露上游配置。
  6. 用积分账户与不可变流水追加结算能力，现有用量记录作为底层计量来源。
  7. 以功能开关按影子计费、软限制、硬限制分阶段启用。

5. 处理流程详细设计

flowchart TD
  A["成员提交生成"] --> B["认证并解析公司"]
  B --> C{"公司和账号启用"}
  C -- 否 --> X["拒绝"]
  C -- 是 --> D{"模型获公司及成员授权"}
  D -- 否 --> X
  D -- 是 --> E["解析公共/公司专属渠道"]
  E --> F["估算最大积分"]
  F --> G{"公司余额、周期及成员上限通过"}
  G -- 否 --> X
  G -- 是 --> H["事务预占积分"]
  H --> I["执行供应商任务"]
  I --> J{"任务结果"}
  J -- 成功 --> K["按实际用量结算并释放差额"]
  J -- 失败/取消 --> L["按失败策略结算或释放"]
  K --> M["写用量、流水、审计"]
  L --> M

任务创建、预占余额与并发占位必须在一致性边界内完成；同一任务通过唯一结算键保证重复完成处理不重复扣分。当前执行为同进程任务路径，不新增供应商 webhook。

13. 日志 / 监查 / 运用设计

  • 公司创建、停用、管理员变更、成员归档、模型授权、渠道绑定、积分调整、计费模式覆盖、Hard 恢复和价格发布必须审计。
  • 平台与公司 CSV 导出均记录操作人、数据范围、筛选条件、时间窗、结果行数和时间；审计失败不返回文件。
  • 公司管理员查看提示词、项目正文、生成结果或附件时记录查看人、目标成员、资源、用途和时间。
  • 监控余额为负、预占超时、重复完成处理、结算失败、公司跨域访问拒绝、渠道路由失败和价格缺失。
  • 积分流水首期由防篡改触发器禁止正常 DML 更新或删除，纠错只能追加；独立应用 DB 角色与 REVOKE 属部署增强。
  • 日志禁止记录密码、会话令牌、API Key 明文、媒体 token/stream handle、预签名地址和完整供应商响应。

15. 数据迁移 / 初期数据 / 兼容性

  1. 项目未上线，直接采用新结构建表；users.company_id 列可空并通过角色条件 CHECK 强制普通用户非空、平台管理员为空，不编写旧字段兼容、回填或双路径分支。
  2. 开发/测试数据库通过 seed 重建平台管理员、公司、公司管理员和成员。
  3. seed 显式初始化公司模型授权、默认模型表、供应商渠道绑定、首个价格版本、0 余额积分账户和 app_settings.credit_mode=shadow；公司 credit_mode_override 默认 NULL，不创建活动暂停。
  4. 不创建个人组织；平台管理员保留平台角色且 companyId 为空。
  5. 影子计费阶段不因余额为 0 阻断。
