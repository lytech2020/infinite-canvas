## 已确认原则

- [x] 每个普通用户必须且只能属于一个公司，不保留独立个人用户。
- [x] 公司是组织和数据边界，不是共享登录账号。
- [x] 平台管理员配置公司、公司模型、渠道、API Key、公司积分和公司上限。
- [x] 公司管理员不能配置或查看 Key，也不能修改模型积分价格或增加公司余额。
- [x] 公司管理员可以添加、管理和归档本公司成员，并设置成员模型和消费上限。
- [x] 公司管理员可以查看本公司成员项目、提示词和生成内容，敏感访问必须写审计。
- [x] 归档成员不能登录或产生新数据，历史数据、用量和审计继续保留原归属。
- [x] 公司拥有唯一真实积分账户；成员拥有周期消费上限而不是独立钱包。
- [x] 文本、图片、视频和音频底层用量统一换算为整数积分。
- [x] 积分采用预占、结算、释放流程，历史保存价格规则快照。
- [x] 专属 Key 只决定调用路由，仍按平台积分规则结算。
- [x] 先影子计费，再软限制，最后按公司逐步启用硬限制。

## 首期明确不做

- 在线充值、支付、发票、自动续费和套餐购买。
- 公司管理员自行配置 Key 或自定义模型价格。
- 成员钱包、成员积分转账、赠送或提现。
- 用户同时加入多个公司、个人空间或跨公司协作。
- 物理删除员工账号及其历史数据。
- 公司管理员批量导出提示词、生成内容或附件。
- 公司专属访问 URL / 自定义域名；它与供应商调用 Base URL 是两项不同能力。
- 旧结构兼容、业务数据回填或双路径迁移；开发和测试数据通过 seed 按新结构重建。

## 推荐开发顺序

1. 公司主数据、平台管理和公司状态校验。
2. 用户唯一公司关系、公司角色、成员管理和账号归档。
3. 所有账号业务数据增加公司归属并完成服务端隔离。
4. 公司模型授权、成员模型授权和最终模型列表过滤。
5. 公司专属渠道、Key 权限和生成路由。
6. 模型价格版本、积分账户、公司/成员上限和影子计费。
7. 预占、结算、释放、退款、核对和硬限制。
8. 三级用量、敏感内容审计、seed 初始化、监控与运维。

## 功能验收

### 公司与成员

- [ ] 平台管理员可以创建、编辑、启用和停用公司。
- [ ] 创建公司时可以设置首个公司管理员，不产生公司共享登录凭据。
- [ ] 公司停用后成员全部会话失效，不能发起新业务请求。
- [ ] 公司管理员只能管理本公司成员。
- [ ] 同一邮箱账号不能加入第二家公司。
- [ ] `POST /api/v1/auth/register` 和 `registration_open` 已下线，不存在 companyId 为空的普通用户。（FP-ORG-002 / VAL-FP-ORG-002-004 / TEST-FP-ORG-002-004）
- [ ] 成员首次登录必须修改一次性初始密码，未改密前只能访问改密和退出接口。（FP-ORG-002 / VAL-FP-ORG-002-005 / TEST-FP-ORG-002-005）
- [ ] 公司管理员不能修改自己的角色、模型授权或消费上限，也不能管理同级公司管理员。（FP-ORG-002 / PERM-FP-ORG-002-002 / TEST-FP-ORG-002-006）
- [ ] 不能归档或降级最后一个有效公司管理员。
- [ ] disabled 与 archived 均立即撤销现有会话；认证拒绝顺序为 archived、disabled、company disabled、must change password。
- [ ] 成员归档后不能登录，但历史项目、素材、生成、提示词、Agent 数据和用量仍可查询。

### 数据隔离

- [ ] `projects`、`user_data`、`uploads`、`upload_references`、`generation_jobs`、`ai_usage_records` 均保存 companyId 和 userId；`user_data` 继续采用 KV。（FP-ORG-003 / DB-FP-ORG-003-001 / TEST-FP-ORG-003-001）
- [ ] 普通成员只能访问本人数据。
- [ ] 公司管理员可以访问本公司成员数据，但不能访问其他公司。
- [ ] 列表、详情、更新、删除、导出、媒体代理和预签名上传均执行服务端公司校验。
- [ ] 跨公司资源访问统一返回 404，不暴露资源是否存在。
- [ ] 对象存储键直接使用 `companies/{companyId}/{userId}/...` 新格式，不保留旧前缀兼容分支。（FP-ORG-003 / DB-FP-ORG-003-002 / TEST-FP-ORG-003-005）
- [ ] Agent 内容审查以 thread blob 为一次审计粒度；thread 内仍按 threadId、turnId、itemId 保持归属和去重。（FP-ORG-003 / TEST-FP-ORG-003-004）
- [ ] canvas-agent 是本地进程且不直接访问云端后端；Agent 线程和附件由浏览器通过 `/api/v1/user-data` 的 `agent_chat` 命名空间及 `/api/v1/uploads` 保存。后端忽略请求体 companyId，只从会话解析公司。（FP-ORG-007 / TEST-FP-ORG-007-006）
- [ ] 公司管理员查看媒体时先写审计，再获得 TTL≤60 秒的一次性兑换 token；兑换后生成仅同会话同 upload 可用的 TTL≤60 秒 stream URL，允许 Range 请求并返回 `Cache-Control: no-store, private`，不返回对象存储预签名下载地址。（FP-ORG-003 / DB-FP-ORG-003-004 / TEST-FP-ORG-003-005）

### 模型、渠道和 Key

- [ ] 平台管理员可以给公司授权模型。
- [ ] 公司管理员只能从公司已授权模型中给成员授权。
- [ ] 成员模型列表只返回平台启用、公司授权、成员授权且有可用路由的交集。
- [ ] 平台管理员可以为公司配置专属渠道和 Key。
- [ ] Azure 公司专属 Provider 可以覆盖 Deployment/远端模型名与 API Version，且不影响公共 Provider。（FP-ORG-005 / DB-FP-ORG-005-002 / TEST-FP-ORG-005-003）
- [ ] 公司 Provider 与模型的 `apiFormat` 必须一致，不一致时保存绑定和运行路由均拒绝。（FP-ORG-005 / TEST-FP-ORG-005-004）
- [ ] 公司管理员和成员的接口、页面及日志均不暴露 Key、密文、Base URL 或供应商账号。
- [ ] Provider 的 scope/companyId 组合由数据库 CHECK 约束：platform 必须无 companyId，company 必须有 companyId。
- [ ] 专属渠道优先，公共渠道是否回退由平台管理员显式配置。
- [ ] 切换渠道不会改变历史积分和用量归属。

### 积分和额度

- [ ] 公司余额、公司周期上限和成员周期上限在界面与服务端明确区分。
- [ ] 公司管理员设置成员上限不会发生积分转账。
- [ ] 公司和成员周期已用统一按“已结算积分 + 当前 active 预占积分”计算。（FP-ORG-006 / VAL-FP-ORG-006-003 / TEST-FP-ORG-006-003）
- [ ] 结算使用预占时锁定的价格版本，跨越价格发布时间不会改变账单。（FP-ORG-006 / VAL-FP-ORG-006-004 / TEST-FP-ORG-006-004）
- [ ] 模型价格按版本发布，发布后不可修改，历史任务保存价格快照。
- [ ] 文本分别记录输入、缓存、输出和推理 Token 费率。
- [ ] 图片、视频、音频按模型实际计费维度计算。
- [ ] 任务提交前按最大可能消费预占积分。
- [ ] 成功后按实际用量结算并释放差额。
- [ ] 失败、取消和供应商已计费失败按明确策略退款或结算。
- [ ] 同一任务重复请求或重复完成处理不会重复预占或扣分；refund、compensate 和管理员调整也有稳定幂等键。
- [ ] refund/compensate 使用调用方 Idempotency-Key；相同键返回原结果，不同键允许同一 job 分次退款或同原因多次合法补偿。
- [ ] 首期同一 job 不自动重试供应商；用户重试会创建新的 requestId、jobId 和预占。（FP-ORG-006 / TEST-FP-ORG-006-005）
- [ ] 并发请求不会使公司积分余额变成负数。
- [ ] 余额人工纠错只能追加调整流水，不能修改历史流水。

### 用量、内容与审计

- [ ] 平台管理员可以查看全平台及单公司的用量、积分和失败情况。
- [ ] 公司管理员可以查看本公司的余额、预占、成员用量、模型分布和积分流水。
- [ ] 普通成员只能查看自己的上限、已用、剩余和任务明细。
- [ ] 归档成员在历史报表中保留并明确标记。
- [ ] 公司管理员打开项目正文、提示词、生成结果或附件前必须写入敏感访问审计。
- [ ] 审计写入失败时不得展示敏感内容。
- [ ] 公司用量 CSV 默认不包含提示词和生成内容。
- [ ] 公司用量导出动作本身写入公司审计日志。（FP-ORG-007 / PERM-FP-ORG-007-003 / TEST-FP-ORG-007-004）

## 非功能验收

- [ ] 积分账户更新、任务创建和预占具有事务一致性。
- [ ] 预占与结算使用唯一幂等键。
- [ ] 定时任务能够安全回收确认无活动任务的超时预占。
- [ ] 应用启动期 stale job 清理与 active reservation 释放在同一事务完成。
- [ ] 每日核对账户余额、积分流水、活动预占和结算记录的一致性。
- [ ] 监控价格缺失、结算失败、预占积压、越权访问和归属缺失。
- [ ] 密码、会话令牌、API Key、预签名地址和完整供应商错误不写日志。
- [ ] 租户关键索引覆盖 companyId、userId、createdAt 和常用筛选条件。

## 阶段发布门槛

### Shadow：影子计费

- [ ] 所有启用模型均存在生效价格版本。
- [ ] 记录理论积分，不改变余额，不阻断请求。
- [ ] 使用构造的 capability × 参数组合用量样例矩阵执行价格试算，并人工核对积分结果。
- [ ] estimated 用量和 provider 用量可分别统计。
- [ ] Shadow 完整执行 reserve → settle → release，记录 shadow 事件但不改变真实余额、不阻断请求。
- [ ] Shadow/Soft/Hard 切换只影响新任务，在途任务始终以 reservation.mode 完成；模型全局容量限制在所有模式仍可拒绝。

### Soft：软限制

- [ ] 展示余额、公司上限、成员上限和预警。
- [ ] 达到限制时提示但不阻断，收集误报和运营反馈。
- [ ] 余额及周期用量达到 80% 和 100% 时可见预警。

### Hard：硬限制

- [ ] 预占、结算、释放和失败策略通过并发与幂等测试。
- [ ] 先对指定测试公司启用，再逐公司扩大。
- [ ] 可以通过独立功能开关立即关闭硬限制。
- [ ] 关闭硬限制不会删除或改写已经产生的正式流水。
- [ ] companyId+modelId 因超预占被暂停后，只能由平台管理员在修正价格、完成对账和 Shadow 试算通过后填写原因并审计恢复。

## 发布前仍需确认

- [ ] 各模型首版积分价格及界面显示比例。
- [ ] 公司停用时已经提交的任务是否允许完成；当前设计推定允许完成结算。
- [ ] 是否接受“公司管理员掌握一次性初始密码，在成员首次改密前理论上可冒充”的残余风险；密码重置首期仅允许平台管理员执行并强审计。
- [ ] 归档成员是否允许恢复；当前设计推定仅平台管理员可恢复。
- [ ] 业务数据与审计日志的正式保留期限。
- [x] 敏感访问原因采用 quality_review、compliance_review、support_troubleshooting、employee_offboarding、security_investigation、other；other 需要补充说明。
