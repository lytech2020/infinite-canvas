# 积分日元定价与利润测算

本文为首版商业定价建议，用于在 Shadow 阶段验证积分售价、模型成本和直接毛利。正式售价仍需以 Azure 实际账单、合同折扣、真实用量结构和税务口径确认，不直接修改模型价格版本。

## 1. 建议结论

- 标准售价：**1 积分 = 250 日元（税前）**，日本含税展示为 **275 日元/积分**。
- 大额套餐：实际成交价建议控制在 **220～240 日元/积分（税前）**。
- 长期价格底线：不建议低于 **200 日元/积分（税前）**；该价格下高输出文本的直接毛利仅约 38%，难以覆盖支付、服务器、存储、流量和运营成本。
- 视频首期建议只开放 `sora-2` 官方支持的 720p；如果开放 `sora-2-pro` 1080p，应将价格提高到至少 **0.9～1.0 积分/秒**。

这里的“直接毛利”仅为积分销售收入减去 AI 供应商调用成本，不包含消费税、支付手续费、退款、服务器、对象存储、网络流量、客服和研发成本。

## 2. 测算基准

内部测算使用以下保守参数：

```text
1 积分 = 1,000 units
1 USD = 165 JPY（内部结算缓冲汇率）
标准售价 = 250 JPY / 积分（税前）
```

汇率缓冲高于日本银行近期美元兑日元市场中间价，用来吸收短期波动和账单换汇差异。模型价格参考：

- [Microsoft Foundry GPT-5.6 定价](https://azure.microsoft.com/en-us/blog/gpt-5-6-now-available-in-microsoft-foundry/)：Standard Global 下，GPT-5.6 Sol 输入 `$5 / 1M Token`、缓存输入 `$0.50 / 1M Token`、输出 `$30 / 1M Token`。
- [OpenAI API 定价](https://platform.openai.com/pricing)：GPT Image 2 按文本及图像 Token 计费；Sora 2 720p 为 `$0.10 / 秒`，Sora 2 Pro 1080p 为 `$0.70 / 秒`。
- [日本银行外汇市场数据](https://www.boj.or.jp/en/statistics/market/forex/fxdaily/fxlist/index.htm)：用于定期校准内部缓冲汇率。

Azure 的地区、Data Zone、合同折扣和税务处理可能产生不同价格。正式结算应以 Azure 实际账单为权威，公开价格只作为首版 Shadow 基准。

## 3. 文本模型毛利

当前 GPT-5.6 Sol 积分规则：

| 计量项 | 当前积分价 | 供应商成本 | ¥250/积分的收入 | 直接毛利率 |
| --- | ---: | ---: | ---: | ---: |
| 非缓存输入 1,000 Token | 10 units | ¥0.825 | ¥2.50 | 67.0% |
| 缓存输入 1,000 Token | 2 units | ¥0.0825 | ¥0.50 | 83.5% |
| 可见输出 1,000 Token | 40 units | ¥4.95 | ¥10.00 | 50.5% |
| 推理 Token 1,000 Token | 40 units | ¥4.95 | ¥10.00 | 50.5% |

输出与推理 Token 是当前积分表中单位积分成本最高的常用项目：

```text
1 积分可结算 25,000 输出 Token
供应商成本 = 25,000 / 1,000,000 × $30 × ¥165
          = ¥123.75

标准售价直接毛利 = ¥250 - ¥123.75 = ¥126.25
标准售价直接毛利率 = 50.5%
```

如果大额套餐按 220 日元/积分成交，同一极端高输出结构的直接毛利为 96.25 日元，直接毛利率约 43.8%。因此 220 日元适合作为折扣底线，而不是标准售价。

### 典型短文本任务

输入 800 Token、输出 300 Token时，按现有规则扣除 20 units，即 0.020 积分：

```text
销售收入 = 0.020 × ¥250 = ¥5.00
供应商成本 = 800 / 1,000,000 × $5 × ¥165
            + 300 / 1,000,000 × $30 × ¥165
          = ¥2.145
直接毛利 = ¥2.855
直接毛利率 = 57.1%
```

文本的实际综合毛利取决于输入、缓存、输出和推理 Token 的比例，Shadow 报表必须分别汇总，不能只用总 Token 推算。

## 4. 图片模型毛利校验

当前 GPT Image 2 按“图片数量 × 尺寸/质量固定积分”收费，但供应商按文本输入、图像输入、缓存输入和图像输出 Token 计费。仅凭尺寸和质量无法准确计算单张成本，尤其图片编辑还会产生参考图输入 Token。

在 250 日元/积分、目标直接毛利率 50% 的前提下，每张图片允许的供应商成本上限如下：

| 尺寸与质量 | 当前积分 | 销售收入 | 50% 毛利允许的最大供应商成本 |
| --- | ---: | ---: | ---: |
| 1024×1024 Low | 0.400 | ¥100 | ¥50 |
| 1024×1024 Medium / Auto | 1.000 | ¥250 | ¥125 |
| 1024×1024 High | 1.800 | ¥450 | ¥225 |
| 1536×1024 / 1024×1536 Low | 0.600 | ¥150 | ¥75 |
| 1536×1024 / 1024×1536 Medium | 1.500 | ¥375 | ¥187.5 |
| 1536×1024 / 1024×1536 High | 2.700 | ¥675 | ¥337.5 |

Shadow 阶段必须按生成和编辑分别采集实际 Token 与 Azure 账单成本。若任一组合的 P95 单张成本超过上表阈值，应提高该组合的积分价，不能用其他图片组合的高毛利补贴未知成本。

## 5. 视频模型毛利与风险

### Sora 2 720p

当前积分规则为 0.300 积分/秒，官方标准价为 `$0.10 / 秒`：

```text
每秒销售收入 = 0.300 × ¥250 = ¥75.00
每秒供应商成本 = $0.10 × ¥165 = ¥16.50
每秒直接毛利 = ¥58.50
直接毛利率 = 78.0%
```

该价格有足够缓冲，可以覆盖实际时长修正、少量失败计费和基础运营成本。

### 1080p 风险

现有设计把 `sora-2` 配置为 480p、720p 和 1080p，但公开价格表中的标准 `sora-2` 只有 720p；1080p 属于 `sora-2-pro`，价格为 `$0.70 / 秒`。如果仍按当前 0.600 积分/秒收费：

```text
每秒销售收入 = 0.600 × ¥250 = ¥150.00
每秒供应商成本 = $0.70 × ¥165 = ¥115.50
每秒直接毛利 = ¥34.50
直接毛利率 = 23.0%
```

该毛利不足以覆盖其他费用。建议调整为：

| 模型与规格 | 建议积分价 | ¥250/积分时直接毛利率 |
| --- | ---: | ---: |
| Sora 2 720p | 保持 0.300 积分/秒 | 78.0% |
| Sora 2 Pro 1024p | 至少 0.700 积分/秒 | 52.9% |
| Sora 2 Pro 1080p | 1.000 积分/秒 | 53.8% |

480p 当前没有对应的公开 `sora-2` 标准价格，进入 Hard 前应确认 Azure Deployment 实际支持范围；无法确认时从参数列表删除，不能按推定低价上线。

## 6. 整体利润判断

以 100 积分为例：

| 售价场景 | 税前收入 | 全部用于高成本输出 Token 时的供应商成本 | 直接毛利 | 直接毛利率 |
| --- | ---: | ---: | ---: | ---: |
| 标准价 ¥250/积分 | ¥25,000 | ¥12,375 | ¥12,625 | 50.5% |
| 套餐价 ¥240/积分 | ¥24,000 | ¥12,375 | ¥11,625 | 48.4% |
| 套餐底价 ¥220/积分 | ¥22,000 | ¥12,375 | ¥9,625 | 43.8% |
| 不建议价格 ¥200/积分 | ¥20,000 | ¥12,375 | ¥7,625 | 38.1% |

在图片实际成本不超过第 4 节阈值、视频规格按第 5 节修正的前提下：

- 高输出文本为主时，直接毛利约 50%；
- 普通文本输入、缓存和输出混合时，直接毛利预计约 55%～70%；
- 720p 视频为主时，直接毛利约 78%；
- 综合直接毛利目标可暂定为 60%～70%，最终必须以 Shadow 的真实业务结构加权计算。

不能把上述直接毛利当作公司净利润。Shadow 报表应另外列出支付手续费、服务器、存储、流量、退款和人工运营成本，形成贡献毛利与最终营业利润口径。

## 7. Shadow 验证与定价调整

进入 Soft 前至少完成以下检查：

1. 每日按公司、模型、能力、规格和 `usageSource` 汇总实际供应商成本、理论积分收入和直接毛利率。
2. 使用 Azure 实际账单验证公开价格，记录地区、计费模式、合同折扣、税务和汇率差异。
3. 图片按生成/编辑、尺寸、质量和参考图数量统计 P50、P95 单张成本。
4. 视频校验实际模型、实际分辨率和实际执行秒数，禁止把 `sora-2-pro` 记为 `sora-2`。
5. 对汇率执行压力测试；内部缓冲汇率不足时发布新的价格版本，不覆盖历史版本。
6. 任一模型或规格的 P95 直接毛利率低于 45% 时继续 Shadow/Soft，并调整积分价；达到 50% 以上后再考虑 Hard。

首版建议采用“积分日元售价稳定、模型 units 价格版本化”的方式调价。供应商价格发生变化时优先调整对应模型积分，而不是频繁改变 1 积分的日元售价。
