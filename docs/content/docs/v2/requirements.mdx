# V2 后续需求

V2 的新增需求、方案和验收清单统一放在本目录。

- [组织账号与公司积分体系](/docs/v2/organization-accounts/acceptance)

## 组织账号与公司积分体系

当前账号体系由单个用户直接持有项目、素材、生成记录和额度。V2 将其调整为“平台管理员 → 公司 → 公司管理员 / 公司成员”的组织账号体系，并以公司作为普通用户业务数据、模型权益、渠道归属、积分和审计的数据边界。

已确认的需求如下：

- 每个普通用户必须且只能属于一个公司，不保留独立个人用户。
- 公司是组织实体，不是多人共享的登录账号；登录主体仍是公司管理员或公司成员。
- AI 供应商渠道（Provider）、供应商调用 Base URL、API Key、Deployment 名称和模型积分价格仅由平台管理员配置，公司管理员不能配置或查看密钥明文；这些上游配置与公司访问本系统的网址无关。
- 删除普通用户自助注册接口和 `registration_open` 设置，普通用户只能由平台管理员或公司管理员创建，且必须绑定唯一公司。
- 公司管理员可以管理本公司成员、成员模型权限和成员消费上限，也可以查看本公司成员的项目、提示词和生成内容；敏感内容访问必须写入审计日志。
- 员工账号采用归档而非删除。归档后不能登录或产生新数据，历史项目、素材、提示词、生成结果、用量和审计记录继续保留在原公司。
- 公司使用统一积分账户，成员获得的是周期消费上限而不是独立钱包。任务同时受公司余额、公司周期上限、成员周期上限和并发上限约束。
- 文本以输入、缓存和输出 Token 为底层计量；图片、视频、音频按各自供应商计费单位计量，再统一换算为整数积分。
- 积分采用“预占 → 结算 → 释放”流程，价格规则版本化，历史任务保存价格快照，积分流水不可直接修改。
- 第一阶段先执行影子计费，验证价格规则；后续依次启用软限制和硬限制。
