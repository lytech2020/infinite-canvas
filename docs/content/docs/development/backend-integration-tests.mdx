# 后台集成测试

后台集成测试使用独立的 Docker Compose 项目、PostgreSQL、MinIO 和模拟 AI 供应商。它不会请求真实模型，不会产生供应商费用，也不会读取或修改本地开发数据库与对象存储。

## 运行测试

确保 Docker 已启动，然后在 `server/` 目录执行：

```bash
npm run test:integration
```

测试命令会自动完成以下操作：

1. 为当前进程分配独立 Compose 项目名和动态宿主端口，避免并行运行互相影响。
2. 构建当前代码对应的前端与后台镜像。
3. 启动名为 `infinite-canvas-test-<运行 ID>` 的隔离 Compose 项目。
4. 自动执行数据库迁移和幂等 seed。
5. 运行 Node 集成测试。
6. 无论成功或失败，默认删除测试容器、网络、数据卷和本次构建的测试镜像。

如果需要保留失败现场：

```bash
TEST_RUN_ID=debug KEEP_TEST_STACK=true npm run test:integration
```

排查完成后手动清理：

```bash
docker compose -f ../docker-compose.test.yml -p infinite-canvas-test-debug down --volumes
```

macOS 找不到 Docker CLI 时，可以显式指定：

```bash
DOCKER_BIN=/opt/homebrew/bin/docker npm run test:integration
```

## 自动覆盖范围

当前共 21 项测试，归纳为 20 组业务场景：

- 全新环境自动迁移、seed、管理员登录及前后台健康检查。
- 登录错误达到固定客户端 IP 的凭据限流后返回 `RATE_LIMITED`。
- 同一 `requestId` 并发提交 20 次只产生一个任务和一条计费记录，并且只真实调用一次模拟供应商。
- 用户普通并发和视频并发严格执行账户限额。
- 模型全局并发在不同用户竞争时严格执行限额。
- 排队和运行中取消时状态保持一致；可控迟到图片结果通过真实 `runJob` 完成结算、覆盖 0 元占位记录，并从 MinIO 删除结果对象。
- 日调用限额、月度金额限额和额度周期重置。
- 管理员跳过次数与金额限制，但仍严格执行任务并发限制。
- 无价格、规格单价未命中、模型能力与计价类型不匹配、零单价、视频缺少计费时长或音频缺少字符兜底时拒绝配置或调用。
- 图片规格价命中、视频按个数与分辨率秒数叠加、Azure OpenAI 视频时长向上适配，以及音频分钟与字符数叠加的成功结算；例如请求 5 秒视频会按供应商实际采用的 8 秒计费。
- 在途任务固定使用创建时的价格规则，追溯新增价格只影响之后创建的任务。
- 使用高精度 Decimal 验证包含输入、缓存、输出、推理 Token 和固定调用费的 `calculationDetail.lines` 与结算金额一致，新增价格规则不会修改历史账单。
- 输出数量、Token、视频时长、消息和提示词硬上限，以及供应商失败后的稳定任务与 0 元记录。
- 生成 60 次、上传签名 120 次的频率限制，以及每用户 100 条待上传记录上限。
- 普通用户不能访问管理读写接口，用户之间不能读取任务、项目或上传文件。
- 停用账号和重新登录、修改密码后的多设备会话撤销、8–16 位密码边界、登录 Cookie 属性，以及缺失或非法请求来源头校验。
- 文件声明大小、实际大小、真实 MIME 类型和跨用户 `uploadId` 校验。
- 下载签名过期后失效，重新查询任务可获得新的有效地址。
- 整个 Compose 项目执行 `down` 后重新 `up`，数据库任务与 MinIO 生成文件继续存在。
- 供应商响应期间终止后台容器，重启后遗留任务变为失败并留下 0 元记录，账号数据继续保留，自动 seed 不会覆盖后台修改过的渠道配置。

测试使用 `server/tests/mock-provider.mjs` 模拟文本、图片、视频和 WAV 音频响应。并发场景通过提示词中的 `[hold=标识]` 停住供应商请求，再由控制接口确认进入数量并精确释放，不再依赖固定睡眠时间；`[delay=毫秒]` 仅用于模拟视频完成时间等非竞争场景。模拟供应商同时提供调用次数统计，用于证明幂等请求没有产生重复外部成本。

测试 runner 为每次运行分配独立项目名和端口，子进程与整套测试都有超时；信号中断和正常结束共用同一个清理 Promise，清理失败会明确报错并令命令失败。生成与上传的 15 分钟频率限制在默认日额度或待上传上限下可能先被其他闸门拦截，因此定位为纵深防御，测试会单独构造可达条件验证它们。

## 仍需人工验收

以下行为依赖真实浏览器环境，不由后台集成测试代替：

- 在画布中生成图片后，确认浏览器可直接加载 `S3_PUBLIC_ENDPOINT` 签发的结果地址。
- 使用非 `localhost` 的 HTTP 地址访问时确认 Cookie 行为。生产环境必须使用 HTTPS，并保持 `SESSION_COOKIE_SECURE=true`。

后续还可增强两类场景：通过真实取消接口精确命中“供应商结果已返回但尚未提交结算”的极窄窗口，以及供应商超时映射为 `PROVIDER_TIMEOUT`。当前可控迟到结果用例通过数据库原子切换取消状态来稳定覆盖容器内的 `runJob → settle → discardResult` 链路，不把它表述为完整取消接口竞态压测。

## 最近验证结果

增强后的测试栈已完整运行通过：21 项通过、0 项失败。后台与测试文件的 TypeScript 检查、测试脚本语法检查及 Compose 配置检查也均通过；测试结束后测试容器、网络和数据卷已自动清理。
