# 画布数据结构

画布业务数据以登录账号为边界保存在云端，浏览器内存只保存当前页面正在使用的状态。退出登录或切换账号时，前端会卸载画布、素材、插件、提示词源和 Agent 状态。

## 云端存储

- PostgreSQL `projects`：保存项目名称、完整画布正文、创建/更新时间及所属用户。
- PostgreSQL `user_data`：保存素材列表、插件、提示词源、生成偏好和 Agent 消息附件引用；图片与视频工作台历史采用索引加单条记录，避免历史增长后超过单行限制。
- PostgreSQL `upload_references`：维护画布及账号业务数据对永久媒体的引用，供孤儿文件清理使用。
- PostgreSQL `uploads`：保存用户上传文件的归属、MIME、大小和对象存储键。
- S3 兼容对象存储：保存图片、视频、音频、参考文件和生成结果本体。

所有读写接口都经过登录校验，并在服务端使用 `userId` 限制访问范围。对象下载通过当前用户校验后签发限时地址。

## 画布项目结构

```ts
type CanvasProject = {
  id: string;
  title: string;
  createdAt: string;
  updatedAt: string;
  nodes: CanvasNodeData[];
  connections: CanvasConnection[];
  chatSessions: CanvasAssistantSession[];
  activeChatId: string | null;
  backgroundMode: "lines" | "dots" | "blank";
  showImageInfo: boolean;
  viewport: { x: number; y: number; k: number };
};
```

项目列表与正文通过 `/api/v1/projects` 加载。编辑时前端先更新内存状态，再防抖写入项目正文；云端保存失败会向用户显示错误提示，不会伪装为保存成功。

## 节点与媒体

节点正文保存在项目 JSON 中。图片、视频和音频节点只保存媒体 `storageKey`、临时展示 URL 和宽高、大小、MIME 等元信息，文件本体不嵌入项目 JSON。

```ts
type CanvasNodeData = {
  id: string;
  type: "image" | "text" | "config" | "video" | "audio";
  title: string;
  position: { x: number; y: number };
  width: number;
  height: number;
  metadata?: {
    content?: string;
    storageKey?: string;
    mimeType?: string;
    bytes?: number;
    prompt?: string;
    status?: "idle" | "success" | "loading" | "error";
  };
};
```

上传流程为：

1. 前端向 `/api/v1/uploads/presign` 申请当前账号的上传地址。
2. 浏览器将文件直传对象存储。
3. 前端调用完成接口，后台校验真实大小和文件类型。
4. 项目或素材只保存返回的上传记录 ID。
5. 页面恢复时用上传记录 ID 换取新的限时下载地址。

导入 ZIP 时文件会重新上传到当前账号，并在导入数据中重写所有旧 `storageKey`，不会沿用其他账号的文件归属。

## 账号生命周期

- `/canvas`、`/canvas/:id`、`/assets`、`/image` 和 `/video` 必须登录。
- 登录或切换账号后重新加载该账号的全部业务 store。
- 退出、会话失效或其他标签页退出时立即清空当前业务内存和 Agent 连接状态。
- 异步加载使用版本号隔离，旧账号的慢请求不能覆盖新账号状态。
- 浏览器仅持久化主题、语言、面板尺寸等设备界面偏好，不持久化业务列表、文件或账号凭据。
